# Story 1.3: Commit 03 - Autenticação e autorização (RF-01)

**Epic:** Organização de Recursos - Base executável
**Story ID:** 1.3
**Sprint:** Commit 03
**Priority:** Critical
**Status:** Review
**Type:** Feature

## User Story

**Como** usuário ativo, **quero** entrar com e-mail e senha e usar um token de acesso, **para** acessar somente as operações permitidas ao meu papel.

## Escopo e decisões

- RF-01: login em `/api/v1/auth/login`, BCrypt, JWT HS256, Spring Security stateless, 401/403 uniformes em português.
- Reutilizar `users`, `roles`, `user_roles` e `AuditService` do Commit 02. Preservar Flyway V1.
- `JWT_SECRET` obrigatório exclusivamente no ambiente do processo, em Base64 padrão com pelo menos 32 bytes aleatórios; `sub` é UUID de usuário. O banco é consultado em cada requisição autenticada para bloquear usuários desativados e refletir papéis atuais.
- Apenas login, health e Swagger/OpenAPI são públicos. Endpoints artificiais de autorização ficam exclusivamente em `src/test`.
- O seed local só usa `LOCAL_SEED_PASSWORD` quando presente; sem ela, gera hash de senha aleatória desconhecida. Nunca altera usuários existentes.
- Sem endpoints de recursos, reservas, manutenção, aprovação ou auditoria neste incremento.

## Acceptance Criteria

1. Login válido de usuário ativo retorna JWT assinado HS256; senha incorreta, usuário inexistente ou inativo recebem 401 genérico.
2. Chave JWT somente do ambiente do processo, Base64 padrão e com pelo menos 32 bytes; expiração limitada; assinatura, emissor e validade temporal verificados.
3. A cada requisição com token, usuário é consultado por UUID e seu estado ativo e papéis atuais são verificados; inativo recebe 401.
4. Os papéis `SOLICITANTE`, `RESPONSAVEL` e `ADMINISTRADOR` tornam-se authorities `ROLE_*`; acesso insuficiente recebe 403.
5. Login, health, Swagger e OpenAPI públicos; demais rotas `/api/v1/**` autenticadas, sem endpoints de teste no artefato principal.
6. Erros 400/401/403 contêm `code`, `message`, `fieldErrors`, `traceId`, sem stack trace ou dados sensíveis.
7. Seed de desenvolvimento somente `local`, senha opcional via ambiente, sem valor padrão, sem redefinir senha existente; testes usam fixtures isoladas.
8. Os sete testes anteriores continuam passando com PostgreSQL/Testcontainers; migration V1 permanece intocada.
